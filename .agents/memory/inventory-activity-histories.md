Related inventory Activity transactions should appear as one summary with an expandable, printable history. This includes batch operations, not just individual removed systems/modules.

**Why:** The user approved the grouped view and explicitly added: "This should apply to batch operations as well. show one summary and a printable history."

**How to apply:** Follow recorded business relationships, including equipment included in a batch. Never group merely because serials, item names, locations or notes match. Grouping is presentation, not permission to merge or rewrite the underlying ledger.

Filters must match an individual transaction's conditions together. A matching summary retains its complete authorized history, including events outside the current filters, with that scope stated on screen and in print.

**Why:** Combining an action from one event with a date from another creates misleading matches. Removing earlier custody events from a filtered history conceals the sequence the user asked to print.

**How to apply:** Keep full transaction detail and original per-transaction quantities. Do not add quantities across repeated custody changes. Preserve the existing separate scanned/visually inspected serial manifests when printing a batch history.

Fulfillment completion and saved-batch screens should offer one combined batch receipt, not multiple indistinguishable print buttons for individual movements.

**Why:** The user found the separate pull and handoff print buttons confusing and explicitly requested a combined receipt in both places.

**How to apply:** Print the full batch-related pull, handoff and release history in one document with separate custody totals. Preserve the underlying movement receipts and their chronological evidence; combining presentation must not combine or rewrite stock postings.
